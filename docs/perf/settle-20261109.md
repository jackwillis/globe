# Settle path, host measurements — 2026-11-09

Issues [#64](https://github.com/jackwillis/globe/issues/64) (parent), #65, #66, #67. **Host only; no
G4 or bare OS 9 number is claimed here.** The G4 savings below are projections from instruction share
and need a hardware A/B (which needs the owner's approval).

## Method

- Host: Intel Xeon @ 2.30 GHz (2 vCPUs, shared), Ubuntu 24.04, GCC 13.3, CMake `RelWithDebInfo` with
  `-O2 -g`; the same flags for every build, built from the same base commit `59a732e`.
- `valgrind --tool=callgrind ./globe-line-layer-bench --repeat 1`: whole-process instruction counts
  (includes about 80M of start-up, scene construction and checksum hashing). Deterministic, so the
  differences are real instruction savings; it is not a time. Different compilers and `-Os` on Classic
  can change the ratio.
- Wall: `globe-line-layer-bench --repeat 7`, medians. Noisy (shared VM); only large gaps mean anything.
- Correctness: the bench checksums `9c714394f3f2bd41` (radius 220) and `e1e923186a7e528d` (radius 440)
  are identical for every build, and the new tests compare pixels (below).

Raw output: `settle-20261109-host-base.json`, `settle-20261109-host-lists.json`,
`settle-20261109-host-lists-ocean.json`.

## Not measured

- Any G4 or OS 9 time. By instruction share the per-cell scan was roughly 60 to 100 ms of the 540 ms
  NetBSD settle and the ocean skip removes about half the cell fills; neither is a measurement.
- Memory on the target: the lists add 260 KB per 1 degree grid (see the PR for #66).
- Retro68 (`-Os`, GCC 16.1.0) code generation; whether `ceil` was a library call there.
